# Виджеты

Строки меню: что бывает, какие поля принимает каждая, как повесить на строку
меню правой кнопки и настройки. Про привязки — отдельно, в [привязках](binds.md).

Общие поля у всех: `Text`, `Desc` (текст нижней панели при наведении),
`Flag`, `Save`, `Enabled`, `Callback`, `Menu`, `Settings`, `Bind`.

Общее у всех обработчиков: `:Get()`, `:Set(v, silent)`, `:SetEnabled(on)`,
`:IsEnabled()`. Второй параметр `Set` везде один и тот же — «не звать
`Callback`»; им пользуются, когда значение ставят изнутри.

**Доли подписи и значения** правятся у строки отдельно: `LabelFrac` и
`ValueFrac`. Умолчания рассчитаны на страницу вкладки, а в меню правой кнопки
шириной 220 те же доли дают под значение полсотни пикселей, и `NO COOLDOWN`
превращается в `NO`. У строки с длинным значением и коротким названием
соотношение обратное обычному, и поправить его надо на месте.

```lua
tab:Toggle({ Text = "ESP", Default = false, Callback = function(on) end })

tab:Button({ Text = "REJOIN", Value = ">", Callback = function() end })
-- :SetValue(text) -- поставить свою подпись справа
-- :SetText(text)  -- сменить название строки; есть и у Keybind

tab:Label({ Text = "ЗАГОЛОВОК" })      -- или tab:Label("ЗАГОЛОВОК")
tab:Divider()

tab:Slider({ Text = "SPEED", Min = 16, Max = 100, Step = 1,
             Default = 16, Suffix = " ст/с", Callback = function(v) end })
-- по числу можно щёлкнуть и ввести руками

tab:InputText({ Text = "WEBHOOK", Placeholder = "https://...",
                MaxLength = 200, Width = 0.42,
                Callback = function(text) end,   -- по завершении ввода
                Changed  = function(text) end })

tab:Dropdown({ Text = "MASK", Options = { "A", "B" }, Default = "A",
               MaxVisible = 6, Search = true, Callback = function(v) end })

tab:MultiDropdown({ Text = "ESP", Options = { "A", "B" }, Default = { "A" },
                    Callback = function(list) end })

tab:Keybind({ Text = "PANIC", Default = Enum.KeyCode.G,
              Callback = function() end,        -- нажали привязанную клавишу
              Changed  = function(key) end })   -- переназначили

tab:ColorPicker({ Text = "ENEMY", Default = Color3.fromRGB(255, 40, 40),
                  Callback = function(c) end })

tab:Radio({ Text = "MODE", Options = { "A", "B" }, Default = "A" })
tab:Segmented({ Text = "SPEED", Options = { "LOW", "MID", "HIGH" } })

local bar = tab:Progress({ Text = "LOADING", Default = 0 })
bar:Set(0.42)                -- доля 0..1
bar:SetValue("42 / 100")     -- своя подпись вместо процентов
bar:SetValue(nil)            -- вернуть проценты
```

Полоса из общего правила не выпадает: подпись у неё ставится `SetValue`, тем же
примитивом, что и у кнопки, а второй параметр `Set` значит `silent`, как и
везде.

`MaxLength` у поля ввода считается **в символах, а не в байтах**: `200` — это
двести букв на любом алфавите, и обрезка всегда падает на границу буквы. В UTF-8
кириллическая буква занимает два байта, и наивный счёт срабатывал бы вдвое
раньше обещанного, а на границе рубил букву пополам.

`Radio` — единственный, у кого **нет правой кнопки**: он занимает не строку, а
несколько строк с подписью над ними, и вешать меню не на что. `Menu` и
`Settings` у него — явная ошибка, а не молчание. Нужен выбор из немногих с
настройками — `Segmented`.

## Списки: форма пункта

```lua
"NAMES"                                       строка = и ключ, и подпись
{ Text = "Игрок", Key = 12345 }               ключ отдельно от подписи
{ Text = ..., Key = ..., Settings = {...} }   плюс свои настройки пункта
```

Раздельные ключ и подпись нужны там, где подписи могут совпадать: на строковом
ключе два разных объекта склеятся в один пункт. Наружу и в профиль при этом
уходит **ключ**, а в строке показывается **подпись**.

`Default = false` — «ничего не выбрано». Это не то же, что промолчать: без
`Default` одиночный список сам отмечает первый пункт, и строка выглядит так,
будто выбор уже сделан.

## Списки: динамика

```lua
dd:Refresh(newOptions)   -- заменить набор целиком
dd:Options()             -- текущие ключи
dd:Prune()               -- забыть выбор и настройки исчезнувших ключей
dd:Has(key)              -- отмечен ли (только у MultiDropdown)
dd:Settings(key)         -- весь набор настроек пункта
```

Выбор и настройки хранятся **по ключу** и переживают пересборку. Исчезнувший
ключ не стирается: его некому показать, и в `Get` он не попадёт. Вернулся ключ —
вернулась отметка. Явная зачистка — `Prune`.

## Списки: настройки отдельных пунктов

Правая кнопка по пункту открывает его настройки. Пункт «с настройками» — это
просто пункт, у которого есть запись в `Settings`; остальные на правую кнопку
не отзываются и помечаются точкой справа.

```lua
tab:MultiDropdown({
    Options = { "NAMES", "BOX", "DISTANCE" },
    Settings = {
        NAMES = { Color = Color3.new(1, 1, 1) },
        BOX   = { Color = Color3.new(1, 0, 0), Outline = true },
    },
    OnSetting = function(key, field, value) end,
})

dd:GetSetting("BOX", "Color")
dd:SetSetting("BOX", "Outline", false)
```

Тип контрола выводится из значения по умолчанию: `Color3` — образец с палитрой,
`boolean` — переключатель, `EnumItem` — захват клавиши (`Escape` отменяет,
`Backspace` снимает — тогда в настройке лежит `false`). Пока идёт захват,
нажатие принадлежит только этой строке — см. [привязки](binds.md#назначение-клавиши).

Тип решает **объявление**, а не то, что лежит в состоянии сейчас: снятая клавиша
не превращает строку в переключатель.

Значение, из которого контрол не выводится, — **ошибка при постройке строки**, а
не пустая строка в окошке. Самая частая опечатка ровно такая: `1000` вместо
описания ползунка — по голому числу диапазон не угадать.

Исключение одно — ползунок: по голому числу диапазон не угадать, поэтому ему
нужна форма описания.

```lua
Settings = {
    ["ЗНАЧЕНИЕ"] = { Type = "Slider", Default = 1000,
                     Min = 1, Max = 999999, Step = 1 },
}
```

**Русское имя настройки пишется через `["..."]`, и это не украшение.** Ключ вида
`ЗНАЧЕНИЕ = ...` — идентификатор, а идентификаторы в Luau только из латиницы:
`{ Цвет = ... }` не компилируется вовсе. Имя настройки видно человеку в окошке,
поэтому русские имена тут дело обычное — и форма у них ровно такая.

В состоянии, в `GetSetting` и в профиле лежит **само число**, а не описание.
Точное значение набирается прямо в поле: дорожка короткая, и по ней в диапазон
до миллиона не попасть.

## Настройки у обычной строки

Тот же механизм доступен **любой** строке, а не только пунктам списка: ползунку,
палитре, полю ввода, кнопке. Подключает их каркас строки, поэтому новый виджет
получает настройки просто потому, что он строка. Строка с настройками помечается
точкой справа.

```lua
tab:Toggle({
    Text = "ПОЛЁТ",
    Settings = { ["Клавиша"] = Enum.KeyCode.F, ["Цвет"] = Color3.new(1, 0, 0) },
    OnSetting = function(field, value) ... end,
})

row:GetSetting("Цвет")
row:SetSetting("Цвет", Color3.new(0, 1, 0))
```

Настройки строки **идут в профиль** наравне со значением: клавиша, цвет и режим —
такие же настройки, как сам тумблер. При загрузке профиля вызывается
`OnSetting`, поэтому значение не просто запоминается, а применяется.

У списка `Settings` означает другое — настройки **пунктов**, по набору на ключ.
Это два уровня против одного, поэтому у него и вызовы двухключевые:
`GetSetting(ключ, поле)`.

## Меню правой кнопки

`Settings` выводит контролы из значений и годится, пока нужны цвет, флаг или
клавиша. Когда нужно что-то ещё — есть `Menu`: в него кладутся **любые
виджеты**, те же самые, что и во вкладку.

```lua
local fly
fly = tab:Toggle({
    Text = "FLY",
    Menu = function(m)
        m:Keybind({ Text = "КЛАВИША", Default = Enum.KeyCode.F })
        m:Slider({ Text = "СКОРОСТЬ", Min = 16, Max = 200, Default = 60 })
        m:Segmented({ Text = "РЕЖИМ", Options = { "CFR", "VEL" } })
        m:ColorPicker({ Text = "СЛЕД" })
        m:Divider()
        m:Button({ Text = "OFF", Callback = function() fly:Set(false) end })
    end,
})
```

Меню — это контейнер, такой же как вкладка, блок и колонка, поэтому внутри
работают и `Section`, и `Split`, и любой виджет, который появится позже.

Есть у **любой** строки, а не только у переключателя. Строка с меню помечается
точкой справа. `MenuTitle` задаёт заголовок окошка, `MenuWidth` — ширину.

`Menu` и `Settings` на одной строке **несовместимы, и это ошибка, а не молчание**:
правая кнопка одна, а открыть пришлось бы двоих. Нужно и то и другое — кладите
настройки внутрь `Menu`, там доступны все виджеты, включая `Keybind` и
`ColorPicker`. То же и с привязкой: `Bind` вместе с `Settings` — ошибка.

У строки **с привязкой** меню строится само: редакторы ядра — клавиша и режим —
встают сверху, дописанное в `Menu` идёт под ними через разделитель. Заявка на
правую кнопку при этом одна, и спорить за неё не с кем.

Содержимое строится **сразу**, а не при первом открытии: меню обязано
появляться мгновенно, и платить задержкой в момент нажатия неправильно.

Открыть можно **сразу несколько**, по разным строкам, и сравнить их рядом. Окна
расходятся сами, чтобы не налезать друг на друга; перетащенное запоминает своё
место до конца сеанса (в профиль это не идёт — положение панели не настройка).
Повторная правая кнопка по той же строке своё окно закрывает.

Виджеты внутри меню — обычные виджеты: у них есть `Flag`, они сохраняются в
профиль и умеют `Get`/`Set` наравне с остальными.

## Поиск в списках

`Search = true` добавляет строку фильтра. Находки **ранжируются**, а не просто
отбираются:

| разряд | что значит | пример |
|---|---|---|
| 0 | строка начинается с запроса | `NI` → `NIGEL` |
| 1 | с запроса начинается слово | `WO` → `DENNIS / WOLF` |
| 2 | подстрока где угодно | `NI` → `DENNIS` |
| 3 | буквы по порядку, но не подряд | `dnw` → `DENNIS / WOLF` |

Разряд 3 по умолчанию выключен. Режимы: `"prefix"`, `"word"`, `"substring"`
(он же `true`), `"fuzzy"`.

Регистр **не важен, в том числе у кириллицы**: `антиаим` находит `АНТИАИМ`.
Штатный `string.lower` в Lua знает только латиницу, поэтому приведение регистра
у библиотеки своё — иначе поиск по русским названиям был бы
регистрозависимым, а собственный менеджер привязок ищет как раз по ним.
