# Привязки

Ядро привязок: как скрипт подключается к клавише, что при этом принадлежит
человеку за меню, чем рубильник отличается от взаимодействия и что умеет
менеджер. Показ привязок на экране — в [экране](screen.md).

У библиотеки своё **ядро привязок**. Скриптер говорит, ЧТО делать; клавишу,
режим и имя выбирает человек за меню, и ядро ничего из этого не требует при
объявлении.

```lua
tab:Toggle({ Text = "ПОЛЁТ", Flag = "fly", Bind = true,
             Callback = function(on) ... end })
```

Две строки — и это уже полноценная привязка: она в списке на экране, в менеджере,
у неё правится клавиша и режим, и всё это уходит в профиль.

## Три вещи принадлежат человеку, а не скрипту

| | |
|---|---|
| **клавиша** | какая, и есть ли вообще. По умолчанию её нет, и `NONE` — рабочее состояние, а не «ещё не настроено» |
| **режим** | `ПЕРЕКЛ.` или `ЗАЖАТИЕ`. Скриптер разрешает это явно — `ChangeModeInGame = true` |
| **подпись** | своё имя в своём списке. Личность привязки при этом не меняется: она в `Flag` |

Все три живут в профиле рядом со значением строки и правятся в двух местах:
в меню правой кнопки у самой строки и в менеджере привязок.

## Bind и Binds — различаются целью, а не количеством

```lua
Bind  = true | Enum.KeyCode.F      -- РУБИЛЬНИК: переключает эту строку
Binds = { {...}, {...} }           -- ВЗАИМОДЕЙСТВИЯ: работают с функцией
```

**`Bind` — рубильник.** Цель — сама строка: нажал, функция включилась, нажал,
выключилась. Ворот у него нет и быть не может — выключенную строку иначе нечем
было бы включить. Он один: две привязки, переключающие одну строку, не значат
ничего.

**`Binds` — взаимодействия.** Цель — сама функция. Строка для них **ворота**:
пока она `ON`, они действуют; человек её выключил — они безусловно уходят в `OFF`
и молчат, сколько ни жми. Строку они не трогают никогда. Их сколько угодно.

```lua
tab:Toggle({
    Text = "АНТИАИМ", Flag = "aa", Default = true,
    Callback = function(on) ... end,
    Binds = {
        { Text = "ВЛЕВО",  Flag = "aaLeft",  Key = Enum.KeyCode.Q,
          Kind = "hold", ChangeModeInGame = true, Toggle = look(-45) },
        { Text = "ВПРАВО", Flag = "aaRight", Key = Enum.KeyCode.E,
          Kind = "hold", ChangeModeInGame = true, Toggle = look(45) },
        { Text = "ФРИСТЕНД", Flag = "aaFree", Key = Enum.KeyCode.F,
          Toggle = function(on) ... end },
    },
})
```

Комбинация любая: только рубильник (обычная фича), только взаимодействия (строка
— чистые ворота, клавишей её не переключить), или оба сразу — одной клавишей
рубим функцию, другими работаем с ней.

## Поля привязки

| поле | что значит |
|---|---|
| `Text` | подпись; человек её потом может сменить |
| `Flag` | имя, по которому привязку находят через `binds:Get`. Без него работает, но не находится |
| `Key` | стартовая клавиша. `Enum.KeyCode` или `Enum.UserInputType` (правая и средняя мыши). Нет — `NONE` |
| `Kind` | `"toggle"` \| `"hold"` \| `"action"`; по умолчанию выводится из того, что привязка умеет |
| `Toggle` | `function(on)` — у привязки **своё** вкл/выкл, хранит его ядро |
| `Action` | `function()` — сработало и всё, состояния нет |
| `ChangeModeInGame` | разрешить человеку крутить режим в меню строки |
| `Enabled` | доступна ли |

`Toggle` и `Action` взаимоисключающие, как и `Action` с режимом: у действия нет
состояния — удерживать нечего, переключать нечего. `ChangeModeInGame` у действия
— **явная ошибка**, а не молчаливый отказ: иначе скриптер будет уверен, что дал
выбор, а его не будет.

Левая кнопка мыши не привязывается: ею открывают само ожидание и водят по меню.

## Привязка без строки

```lua
win:Bind({ Text = "ПЕРЕЗАПУСК", Flag = "reload", Key = Enum.KeyCode.P,
           Action = function() ... end })
```

Ни строки, ни ворот: показывать нечего и гасить нечему. Набор полей тот же.

## Назначение клавиши

Левая кнопка по строке клавиши — ожидание нажатия. Правая — настройки самой
привязки: режим и имя.

| в режиме ожидания | что делает |
|---|---|
| любая клавиша, правая или средняя мыши | назначить |
| `Escape` | отменить, оставить как было |
| `Backspace` | снять клавишу совсем |

Пока идёт ожидание, клавиатура принадлежит **ему одному**: ни клавиша открытия
меню, ни другие привязки на это нажатие не отзываются. Поэтому назначать уже
занятую клавишу можно спокойно — занявший от этого нажатия не сработает.

**Ждущий всегда один.** Щёлкнул строку, передумал, щёлкнул соседнюю — прежнее
ожидание отменяется, а не назначается вместе с новым.

## Клавиша выигрывает у игры

`processed` для клавиатуры игнорируется намеренно. Игра вешает свои действия на
`R`, `T`, `G`, `F` и съедает их первой — привязка на такую клавишу не срабатывала
бы никогда, при том что в списке она стоит. Меню ставят **поверх** игры, значит
его привязка обязана выигрывать.

Единственная настоящая причина «нажатие не наше» — **набор текста**, и она
проверяется прямо: есть фокус в поле — привязки молчат. У мыши правило прежнее:
там `processed` означает «щёлкнули по интерфейсу», и это наш собственный
интерфейс.

## Менеджер привязок

```lua
system:Binds({
    Text  = "ПРИВЯЗКИ",   -- подпись строки
    Title = "ПРИВЯЗКИ",   -- заголовок выпавшего окна
    Desc  = "...",        -- нижняя панель при наведении
    Width = 260,          -- ширина окна
    Empty = "привязок нет",
})
```

Менеджер — **высшая инстанция**. В меню строки человек распоряжается тем, что ему
оставил скриптер; здесь — всем, что привязка вообще умеет: сменить режим, даже
если `ChangeModeInGame` не стоял, убрать привязку из списка на экране, снести
совсем. Всё правой кнопкой по её строке.

Сверху — `ДОБАВИТЬ`: список того, что ещё можно привязать. Щёлкнул функцию —
привязка создана, без клавиши и без второго шага; клавиша, режим и имя
настраиваются уже в списке ниже.

`СНЕСТИ` стирает **настройки, а не саму возможность**: клавиша, своё имя, свой
режим и скрытие снимаются, привязка пропадает из списка на экране и возвращается
в `ДОБАВИТЬ`, откуда её можно завести заново.

Не отменяется только физика: у действия режима нет и здесь.

Написан менеджер теми же примитивами, что открыты наружу, — сторонний пишется
ровно так же.

## Ядро наружу

```lua
local core = win.binds

core:All()                  -- копия списка привязок, в порядке объявления
core:Get("fly")             -- по Flag
core:Changed(function(bind, what) ... end)   -- возвращает функцию отписки
core:Capture(function(key) ... end)          -- дождаться нажатия
```

`what` — одно из: `added`, `removed`, `made`, `key`, `kind`, `title`, `shown`,
`enabled`, `held`, `state`. `bind == nil` означает «поимённо не знаем,
пересоберись целиком».

Букета сигналов нет намеренно: виду нужен повод перерисоваться, а не двадцать
подписок, каждую из которых надо не забыть снять.

## Ручка привязки

```lua
bind:Name()          bind:Title()      bind:SetTitle(text)   -- nil вернёт заводскую
bind:Key()           bind:KeyName()    bind:KeyType()        -- "Keyboard" | "Mouse"
bind:SetKey(key)     bind:Capture(fn)
bind:Kind()          bind:SetKind("toggle" | "hold")         bind:CanChangeMode()
bind:Get()           bind:Set(on)      bind:Fire()           bind:Shut()
bind:Held()          bind:Enabled()    bind:SetEnabled(on)
bind:Made()          bind:SetMade(on)  bind:Shown()          bind:SetShown(on)
bind:Gated()         bind:Row()        bind:Reset()          bind:Destroy()
```

`Get()` возвращает три исхода, а не два: `true`, `false` и `nil`. `nil` — это
**действие**, а не «выключено»: у него нет состояния, и в списке ему написано
`[B]`, а не `[OFF]`.

`Made()` — создана ли привязка, отдельно от того, есть ли у неё клавиша.
Скриптер дал `Key` — готова сразу; дал `Bind = true` — объявил возможность, а
создаст её человек. `SetMade(false)` снимает и клавишу: привязки, которой «не
существует», но которая слушает клавишу, не бывает.

`Reset()` — то, что делает `СНЕСТИ`. `Destroy()` — для скрипта, который убирает
фичу целиком; человеку за меню он не предлагается нигде, у него нет способа
вернуть убранное.

`SetKind` **согласует состояние с клавишей**. В `ЗАЖАТИИ` включённое означает
«клавишу держат», в `ПЕРЕКЛ.` — нет, и момент смены режима это единственное
место, где два правила встречаются. Переставили режим у включённого тумблера —
держать некому, значит гаснет; сменили на `ПЕРЕКЛ.`, пока клавишу держат, —
гаснет тоже, иначе отпускание до состояния уже не дойдёт. Гасим, но **не
зажигаем**: включить фичу оттого, что человек ткнул в «режим», — ошибка дороже.

## Двух привязок сразу ядро не рассудит

Зажали две клавиши разом — обе привязки честно в `ON`, каждая со своим
состоянием. Ядро **не арбитр**: оно не знает, что «влево» и «вправо»
противоречат друг другу, — это знание про функцию, а не про клавиши.

Сводит их вместе тот, кто знает, что они означают. Наивное `значение = on and
сторона or 0` для этого не годится: отпускание одной клавиши стирает работу
другой, которую ещё держат. Рабочий образец — стопка зажатых:

```lua
local held = {}

local function look(side)
    return function(on)
        if on then
            held[#held + 1] = side
        else
            for i = #held, 1, -1 do
                if held[i] == side then table.remove(held, i) end
            end
        end
        rotation = held[#held] or 0
    end
end
```

Побеждает последний нажатый; отпустил его — вернулись к тому, что ещё держат.

Две привязки на **одну** клавишу тоже не рассудить: срабатывают обе, в порядке
объявления. Это не ошибка, а иногда и намерение.

## Ни одного цикла

Удержание — `InputEnded`, а не опрос клавиатуры. Состояние — ручка владельца, а
не сверка по таймеру. Актуальность списка — подписка, а не перерисовка каждый
кадр. Ожидание нажатия — временная подписка, а не ожидание в потоке.

Подписок на ввод **две на всё окно**, а не по паре на привязку, и заводятся они
при первой объявленной. Нужная запись достаётся из индекса по клавише: чужое
нажатие стоит трёх проверок и одной выборки из хеша.
